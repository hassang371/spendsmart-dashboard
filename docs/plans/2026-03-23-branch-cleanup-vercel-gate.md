## Section 2: Vercel Production Gate

### Mechanism

Add `vercel.json` at the repo root with an `ignoreCommand`. Vercel evaluates this shell
command before every deploy; **`exit 0` = skip, `exit 1` = build** (Vercel treats non-zero
as "changes detected, proceed" and zero as "nothing to do, skip").

```json
{
  "ignoreCommand": "if [ \"$VERCEL_ENV\" = \"production\" ]; then exit 0; else exit 1; fi"
}
```

### Behaviour table

| Event | `VERCEL_ENV` | `ignoreCommand` exit | Outcome |
|---|---|---|---|
| Push to `main` | `production` | `0` | Deploy **skipped** |
| Push to any feature branch | `preview` | `1` | Preview deploy created |
| Push to `redesign-overview-prototype` | `preview` | `1` | Preview deploy created |

### Pre-push gate verification

Before pushing `main`, verify the command locally:

```bash
VERCEL_ENV=production sh -c 'if [ "$VERCEL_ENV" = "production" ]; then exit 0; else exit 1; fi'; echo "Exit: $?"
# Expected: Exit: 0  (skip)

VERCEL_ENV=preview sh -c 'if [ "$VERCEL_ENV" = "production" ]; then exit 0; else exit 1; fi'; echo "Exit: $?"
# Expected: Exit: 1  (build)
```

### Reverting the gate

When the user explicitly requests a production deploy, change `exit 0` to `exit 1` in
the production branch of `vercel.json`, commit, and push to `main`.

## Section 3: GitHub Secrets

The CI `test-frontend` (next build) and `test-e2e` jobs require two secrets that already
exist in Vercel but must also be added to GitHub repository secrets
(Settings → Secrets and variables → Actions):

| Secret name | Source |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Copy from Vercel env (`vercel env pull`) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Copy from Vercel env (`vercel env pull`) |

The values will be pulled from Vercel locally and the user will paste them into GitHub.
Claude does not handle the secret values directly.

## Execution Order

1. Create and commit `vercel.json` (gate must be in place before any push to `main`)
2. Verify gate locally (`VERCEL_ENV=production` → exit 0, `VERCEL_ENV=preview` → exit 1)
3. Push `main` → `origin/main` (`git push -u origin main`)
4. Push `feat/account-aggregator` → remote (`git push -u origin feat/account-aggregator`)
5. Push `redesign-overview-prototype` → remote (`git push -u origin redesign-overview-prototype`)
6. Confirm stale branches have no unreachable commits: `git log origin/main..origin/<branch> --oneline` → must be empty
7. Delete `origin/add-claude-github-actions-1772887153288`
8. Delete `origin/add-claude-github-actions-1772887261128`
9. Pull Vercel env values → user pastes into GitHub Secrets

## Success Criteria

- `git branch -a` shows no stale remote branches
- `main`, `feat/account-aggregator`, `redesign-overview-prototype` all have upstream tracking (`-u` set)
- Gate verified locally before `main` push (exit codes confirmed correct)
- Vercel dashboard shows next `main` push as "Skipped" (not Error or Ready)
- Vercel previews still build for feature branch pushes
- Stale branches confirmed empty before deletion (`git log` output is blank)
- GitHub Actions CI passes on `feat/account-aggregator` (once secrets are added)

# Incident Runbook: API 503 Service Unavailable

## 1. Overview

**What happened:** The SCALE API is returning HTTP 503 (Service Unavailable) to clients, indicating the gateway or downstream services are down or struggling to process requests.
**Primary SLI Impacted:** Availability (99.9% target).
**Urgency:** HIGH (Critical Alert). Page On-Call immediately.

## 2. Initial Triaging

1. **Validate the Alert:**
   - Attempt to manually hit the API: `curl -I https://api.scalefinance.dev/api/v1/health`
   - If it returns `503` or hangs, the alert is genuine.
2. **Check the Dashboard:**
   - Go to Grafana/Datadog and view the "SCALE Overview" dashboard.
   - Look at the `ApiDown` or `HighErrorRate` panels. Is traffic dropping to 0 (hard down) or just spiking errors (partial degradation)?

3. **Check Cloud Provider/PaaS Status:**
   - Verify if the underlying infrastructure (AWS/GCP/Vercel) has a known outage in our region.

## 3. Investigation Steps

### A. Is the API Container Running?

Run `kubectl get pods -n scale-prod` or check Docker/Render logs.

- If pods are **CrashLoopBackOff**, check application startup logs for configuration errors (e.g., bad database connection strings).
- If pods are **OOMKilled**, the application ran out of memory. Check for memory leaks or massive payloads bypassing limits.

### B. Are Dependencies Down?

Check the `/api/v1/ready` endpoint (or its logs).

1. **PostgreSQL (Supabase):** Check connection pools. Is the DB rejecting connections?
2. **Redis:** Is Redis unreachable causing rate limiter or Celery blocks? (Note: Rate limiter is designed to fail-open, but cache/Celery might fail).

### C. Is the System Overloaded?

Look at CPU/Memory utilization and Request Queue Depth.

- If CPU is pegged at 100%, we might be under a DDoS attack or experiencing a rogue query.
- **Action:** Temporarily scale up replicas (`kubectl scale deployment scale-api --replicas=5`).

## 4. Remediation & Recovery

- **Scale Up:** Add more API instances to handle sudden load.
- **Rollback:** If a deployment happened within the last 15 minutes, revert the deployment. (`git revert`, or rollback via GitHub Actions).
- **Restart:** If pods are deadlocked, forcefully restart them: `kubectl rollout restart deployment scale-api`.

## 5. Post-Incident Requirements (Blameless)

Once the system is restored to health, write a blameless postmortem.

- What caused the 503?
- How much error budget was burned?
- What automation or fix can prevent this specific 503 from happening again?

# Design Docs Trigger Rule

Before writing ANY code for a feature, bug fix, or architectural decision:

1. Read `.claude/skills/design-docs/SKILL.md`
2. Follow its decision tree to determine the doc type
3. Write the doc (LLD, bug report, or RFC) — fill ALL sections, no TODOs
4. Commit the doc before writing any code
5. Only then proceed to implementation

**Why this rule exists:** Docs must be committed before code, not retrofitted after.

The design-docs skill handles everything: templates, Mermaid diagrams, HLD sync, auto-numbering.
